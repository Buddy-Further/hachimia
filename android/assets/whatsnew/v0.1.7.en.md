Hotfix for the critical `v0.1.6` startup regression locking the UI on "Waiting for gateway…", plus a fix for the Extensions GitHub CLI (`gh`) login card getting stuck on "Requesting a one-time code from GitHub…".

## What's New

- **Fix background-thread `CookieManager.setCookie` crash locking startup**: `MainActivity.writeGatewayCookie()` now dispatches 3-argument `CookieManager.setCookie(..., callback)` onto a dedicated main-Looper `Handler` and awaits in-memory CookieStore completion via a bounded `CountDownLatch` (300ms), avoiding Chromium's `IllegalStateException` on Looper-less `ui-prove` / WebView IO threads while keeping `flush()` asynchronous and unaffected by `onDestroy`.
- **Isolate `Env.onBoot` callback failures**: `Env.proveBootOnce()` now calls `onBoot` through `Env.invokeOnBoot()` with an isolated `try/catch (Throwable)` and error logging so a Cookie callback failure can never invalidate an already-verified gateway proof or trigger a 61ms reload-quota exhaustion loop against the 3-second `provedAt` cache.
- **Add diagnostics to `Env.fetchStatic()`**: Log sanitized warnings on non-200 HTTP statuses and exceptions instead of silently returning `null`.
- **Fix Extensions GitHub CLI (`gh`) one-time code never appearing**: `ghLoginEnv()` strips `app/pre` from `PATH` so `gh auth login --web` does not invoke `termux-clipboard-set` and block on a surprise clipboard confirmation dialog, and `parseGhDeviceOutput()` now matches both `First copy your one-time code: XXXX-XXXX` and the clipboard-succeeded `One-time code (XXXX-XXXX) copied to clipboard` format (with ANSI stripping).
